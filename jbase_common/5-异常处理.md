# 异常处理

JBase.Common 提供强大的全局异常处理中间件，统一捕获和处理应用程序中的所有异常。

## 核心组件

| 组件 | 说明 |
|------|------|
| `ExceptionMiddleware` | 全局异常处理中间件 |
| `IExceptionHandler` | 自定义异常处理器接口 |
| `ExceptionHandlerOptions` | 异常处理配置选项 |
| `CommonException` | 业务异常类 |

## 注册中间件

```csharp
public void Configure(IApplicationBuilder app)
{
    // 使用 TraceId 中间件（最早）
    app.UseTraceId();

    // 使用 JWT 中间件
    app.UseJwt();

    // 使用全局异常处理中间件
    app.UseExceptionMiddleware();

    // 其他中间件...
}
```

## 配置选项

### 基础配置

```csharp
// 默认配置已足够大多数场景使用
app.UseExceptionMiddleware();
```

### 自定义配置

```csharp
services.Configure<ExceptionHandlerOptions>(options =>
{
    // 是否启用自定义异常处理
    options.EnableCustomExceptionHandling = true;

    // 自定义异常处理委托
    options.OnExceptionAsync = async (context, exception, message, traceId) =>
    {
        // 记录详细日志
        var logger = context.RequestServices.GetService<ILogger<MyClass>>();
        logger.LogError(exception, "发生异常: {Message}, TraceId: {TraceId}", message, traceId);

        // 发送告警通知
        await SendAlertAsync(exception);
    };
});
```

## 异常类型处理

### 1. 业务异常（CommonException）

```csharp
// 抛出业务异常
ThrowHelper.ThrowCommonException("用户名已存在");

// 或带错误码
ThrowHelper.ThrowCommonException("余额不足", 10001);

// 或使用 CommonException 类
throw new CommonException("操作失败", 10002);
```

业务异常会被中间件捕获并返回：

```json
{
    "success": false,
    "code": 10001,
    "msg": "余额不足",
    "data": null
}
```

> **注意**：实际返回字段为 `success`、`code`、`msg`、`data`（驼峰命名）。

### 2. 参数验证异常（ValidationException）

```csharp
throw new ValidationException("参数不能为空");
```

### 3. 系统异常

未预期的系统异常会被统一处理：

```json
{
    "success": false,
    "code": 500,
    "msg": "服务器繁忙，请稍后再试",
    "data": null
}
```

> **安全提示**：系统异常不会泄露内部错误信息，防止信息泄露。

## 自定义异常处理器

### 实现 IExceptionHandler

```csharp
public class DatabaseExceptionHandler : IExceptionHandler
{
    private readonly ILogger<DatabaseExceptionHandler> _logger;

    public DatabaseExceptionHandler(ILogger<DatabaseExceptionHandler> logger)
    {
        _logger = logger;
    }

    public async Task HandleAsync(HttpContext context, Exception exception,
        string errorMessage, string traceId)
    {
        if (exception is DbUpdateException or SqlException)
        {
            _logger.LogError(exception, "数据库异常: {Message}", errorMessage);

            // 记录到数据库
            await SaveExceptionLogAsync(exception, traceId);

            // 发送告警
            await SendAlertEmailAsync(exception);
        }
    }
}
```

### 注册处理器

```csharp
// 注册处理器（通过 DI 容器）
services.AddScoped<IExceptionHandler, DatabaseExceptionHandler>();
services.AddScoped<IExceptionHandler, ThirdPartyExceptionHandler>();
```

### 处理流程

```
异常发生
    ↓
┌─────────────────────────────────┐
│  ExceptionMiddleware 捕获异常    │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│  判断异常类型                    │
│  - CommonException              │
│  - ValidationException          │
│  - 其他系统异常                  │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│  仅对系统异常执行自定义处理器     │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│  返回标准化错误响应               │
│  { success, code, msg, data }   │
└─────────────────────────────────┘
```

## ThrowHelper 辅助类

### 抛出常用异常

```csharp
using JBase.Common.Helper;

// 抛出业务异常
ThrowHelper.ThrowIfNull(user, "用户不存在");
ThrowHelper.ThrowIfEmpty(list, "列表不能为空");
ThrowHelper.ThrowCommonException("操作失败");
```

### 完整方法列表

| 方法 | 说明 |
|------|------|
| `ThrowIf(condition, message)` | 条件为真时抛出 |
| `ThrowCommonException(message)` | 抛出业务异常 |
| `ThrowCommonException(message, code)` | 抛出带错误码的异常 |
| `ThrowCommonException(message, innerException)` | 抛出带内部异常的异常 |
| `ThrowCommonException(message, innerException, code)` | 抛出带内部异常和错误码的异常 |
| `ThrowIfNull(argument, paramName)` | 值为 null 时抛出 |
| `ThrowIfNullOrWhiteSpace(argument, paramName)` | 字符串为 null、空或空白时抛出 |
| `ThrowIfEmpty(argument, paramName)` | 集合为 null 或空时抛出 |
| `ThrowIfEmpty<T>(argument, paramName)` | 集合为 null 或空时抛出（泛型版本） |

### 使用示例

```csharp
// 对象空检查
ThrowHelper.ThrowIfNull(user, "用户");
ThrowHelper.ThrowIfNull(order, "订单");

// 字符串空检查
ThrowHelper.ThrowIfNullOrWhiteSpace(name, "名称");
ThrowHelper.ThrowIfNullOrWhiteSpace(code, "编码");

// 集合空检查
ThrowHelper.ThrowIfEmpty(userList, "用户列表");
ThrowHelper.ThrowIfEmpty(orderList, "订单列表");

// 带条件的异常抛出
ThrowHelper.ThrowIf(string.IsNullOrEmpty(name), "名称不能为空");
```

## 响应格式

### 成功响应

```json
{
    "success": true,
    "code": 200,
    "msg": "success",
    "data": {
        "id": 1,
        "name": "张三"
    }
}
```

### 错误响应

```json
{
    "success": false,
    "code": 400,
    "msg": "请求参数错误",
    "data": null
}
```

### HTTP 状态码对应关系

| 状态码 | 场景 | 错误消息 |
|--------|------|----------|
| 200 | 成功 | - |
| 400 | 请求参数错误 | ValidationException |
| 401 | 未授权 | 请求头缺少 Token 或 Token 无效 |
| 403 | 权限不足 | 无权访问该资源 |
| 404 | 资源不存在 | 请求的 URL 路径不存在 |
| 429 | 请求过于频繁 | 防高频限制触发 |
| 500 | 服务器错误 | CommonException.GetCode() 或默认消息 |

## TraceId 关联

所有错误响应都会在日志中包含 `traceId`，方便日志追踪：

```json
{
    "success": false,
    "code": 500,
    "msg": "服务器繁忙，请稍后再试"
}
```

响应头中也会包含：

```
X-TraceId: abc123def456
```

## 最佳实践

### 1. 统一异常处理原则

```csharp
// 推荐：在服务层抛出业务异常
public class UserService
{
    public async Task<User> GetUserAsync(int id)
    {
        var user = await _dbContext.Users.FindAsync(id);
        ThrowHelper.ThrowIfNull(user, "用户不存在");
        return user;
    }
}
```

### 2. 避免在控制器层捕获异常

```csharp
// 不推荐：每个方法都 try-catch
[HttpGet("{id}")]
public async Task<IActionResult> GetUser(int id)
{
    try
    {
        var user = await _userService.GetUserAsync(id);
        return Ok(user);
    }
    catch (Exception ex)
    {
        return BadRequest(ex.Message);
    }
}

// 推荐：依赖全局异常处理
[HttpGet("{id}")]
public async Task<IActionResult> GetUser(int id)
{
    var user = await _userService.GetUserAsync(id);
    return Ok(user);
}
```

### 3. 自定义错误码规范

```csharp
public static class ErrorCodes
{
    // 1xxx - 用户相关
    public const int UserNotFound = 1001;
    public const int UserAlreadyExists = 1002;
    public const int PasswordIncorrect = 1003;

    // 2xxx - 订单相关
    public const int OrderNotFound = 2001;
    public const int InsufficientBalance = 2002;

    // 5xxx - 系统错误
    public const int SystemError = 5001;
}

// 使用
throw new CommonException("余额不足", ErrorCodes.InsufficientBalance);
```

### 4. 异常日志记录

```csharp
public class AlertExceptionHandler : IExceptionHandler
{
    private readonly IEmailService _emailService;

    public async Task HandleAsync(HttpContext context, Exception exception,
        string errorMessage, string traceId)
    {
        // 发送告警邮件
        await _emailService.SendAlertAsync(new AlertDto
        {
            Subject = $"系统异常告警 [{traceId}]",
            Content = $"错误消息: {errorMessage}\n异常类型: {exception.GetType().Name}",
            TraceId = traceId
        });

        // 记录到监控系统
        await _monitoringService.ReportExceptionAsync(exception, traceId);
    }
}
```

## 与 Filters 的区别

| 特性 | ExceptionMiddleware | Filter |
|------|---------------------|--------|
| 捕获范围 | 整个管道 | 仅 Controller 层 |
| 执行顺序 | 最外层，最先捕获 | Controller 之前/之后 |
| 适用场景 | 全局统一处理 | Controller 级别逻辑 |
| 无法捕获 | 管道外的错误 | 模型绑定错误 |

> **建议**：同时使用 ExceptionMiddleware（全局）和 Filter（Controller 级别逻辑）。
